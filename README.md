# 公交客流月报 · 换基涨跌判定

公交客流月报在不同版次间更换过基期（各版基期指数均为 100）。本工具接收
**同口径**月报 CSV，在勾选版次并选定起止月份后，依据**与两月相连的全部换基
记录**，严格判定两个月份之间的客流是：

| 判定 | 含义 |
| --- | --- |
| **必涨** | 所有满足公布数据的指数真值都使止月客流高于起月，并给出源记录证明链 |
| **必跌** | 同理，止月客流必然低于起月，并给出源记录证明链 |
| **无法证实涨跌** | 可行比值区间包含 1，现有记录不足以确定方向（同时给出可行区间） |
| **缺少换算依据** | 两月在勾选版次下不存在相连的换基记录链 |
| **记录存在矛盾** | 相连记录构成负权环（指数区间无法同时成立），暂停判定并列出冲突记录 |

## 1. CSV 格式

UTF-8（或 GBK）编码，首行表头，必需四列（中英文表头均可）：

| 列 | 别名 | 说明 |
| --- | --- | --- |
| 版号 | `version` | 同一版次共享一个基期月 |
| 基期月 | `base_month` | 格式 `YYYY-MM`，该月指数定义为 100 |
| 统计月 | `stat_month` / `月份` | 格式 `YYYY-MM` |
| 公布指数 | `index` | 正整数；真值与公布值之差绝对值 ≤ 0.5 |

示例见 [`samples/demo_monthly_reports.csv`](samples/demo_monthly_reports.csv)。
上传时会逐行校验，所有错误一次性返回（含 CSV 行号）；完全重复的行会被忽略
并给出提示；同一版次出现多个基期月会直接报错。

## 2. 快速开始（Docker Compose）

```bash
docker compose up --build
# 浏览器打开 http://localhost:8000
```

页面操作：

1. 上传 CSV，或直接点击载入内置示例（可涨/矛盾/缺依据/备用通路四套）；
2. 勾选参与判定的版次，选择起月、止月；
3. 点击「判定涨跌」，查看结论与证明链 / 冲突记录 / 可行区间；
4. 「下架试算」：勾选拟下架的在架版次、填写要保护的月对（也可只填月对），
   查看下架后立即断开的月对与单版桥接版号，通过后确认。

停止：`docker compose down`。

### 2.1 下架旧版次（试算 → 确认）

公交数据员下架旧版月报时，年报用到的月份必须仍能换基。页面第 4 节：

1. 勾选拟下架版次（只列当前在架版次），可再填若干保护月对；此前已登记的
   月对自动纳入本次试算；每对必须两个不同月份，A/B 颠倒视为同一对；
2. 点击「下架试算」。系统按“当前在架版次 − 拟下架版次”重建换基通路
   （可借用任意中间月份），逐对给出：
   - 下架后**立即断开**的月对；
   - 仍连通的月对中，**整版源行一旦缺失就会断开**的全部版号（单版桥接）。
3. 定义“备用通路”为：下架后仍连通，且**余下任一版整版源行临时取不到时仍
   连通**。只要有一对不满足，确认按钮即禁用。
4. 「确认」会按试算方案**同时**登记新填月对并停用所选版次。确认前会校验
   在架版次与已登记月对是否仍与试算时一致；若不一致（例如另一个标签页先
   提交了变更）返回 409 并提示重新试算。任何失败都不写入，现有供数不变。
5. 同一数据集链接（`http://localhost:8000/?dataset=<id>`）可在多个标签页
   打开；页面提供「刷新当前状态」读取最新在架版次与已登记月对。
6. 原网页的判定区只列在架版次；`/api/analyze` 若收到已下架版号会返回 422，
   但源行仍可通过 `GET /api/datasets/{id}/records?version=...` 查询。

## 5. 判定原理（差分约束 + 最短路径）

设月 `m` 真实客流为 `F(m)`。一条记录（版 `v`，基期 `b`，统计月 `m`，公布
指数 `I`）给出：

```
(I - 0.5)/100 ≤ F(m)/F(b) ≤ (I + 0.5)/100
```

令 `x_m = ln F(m)`，取对数后成为差分约束，转为两条有向边：

- `b → m`，权 `ln((I+0.5)/100)`（比值上界）
- `m → b`，权 `-ln((I-0.5)/100)`（比值下界的反向约束）

对起月 `s`、止月 `e`，令 `d = x_e - x_s = ln(F(e)/F(s))`：

- Bellman-Ford 求 `s → e` 最短路，得 `d` 的上界 `U`；
- 求 `e → s` 最短路，得 `d` 的下界 `L`；
- `U < 0` ⇒ 必跌；`L > 0` ⇒ 必涨；否则区间含 1，无法证实；
- 图中存在负权环 ⇒ 约束无解 ⇒ 记录互相矛盾，回溯前驱边列出环上记录；
- `s`、`e` 不在同一无向连通分量 ⇒ 缺少换算依据。

判定只使用与起、止两月同属一个连通分量且来自勾选版次的记录（即“与两月相连
的全部换基记录”）。证明链由最短路径的前驱边重建，每一步都标注其 CSV 源行号、
所用上/下界及比值区间，各步区间连乘即总体可行区间。

## 6. 下架试算原理

试算与判定共用同一套“记录 → 无向换基通路”模型：

- 用“在架版次 − 拟下架版次”的全部源行建图，月对连通即为下架后仍可换基；
- “下架后立即断开”= 下架前连通、下架后不连通；
- 对每个仍连通的月对，依次排除余下每个在架版次，若排除某版后不连通，
  该版即为单版桥接；排除后仍连通则记录替代通路用于页面核对；
- 确认时会用当前快照重新验证全部月对，并校验 `revision`、在架版次与已登记
  月对与试算快照一致，然后一次性写入（登记月对 + 停用版次 + `revision + 1`）。

## 7. 目录结构

```
app/
  logic.py          # 解析、建图、Bellman-Ford、判定、下架试算（纯标准库）
  main.py           # FastAPI 路由（上传/示例/判定/记录/试算/确认）
  static/index.html # 单页前端（判定 + 下架试算）
samples/            # 四套内置示例 CSV
tests/              # pytest 用例（逻辑 + API）
Dockerfile, docker-compose.yml, requirements.txt
```

## 8. 说明与限制

- 数据集保存在进程内存中（演示用途），重启服务后需重新上传；
- 试算快照也保存在进程内，最多保留最近 20 个；
- 同一数据集的多标签页共享同一内存状态；确认接口用进程锁串行化，演示部署
  为单进程 uvicorn，多 worker 部署不作为目标；
- 月份按 `YYYY-MM` 字符串处理，字典序即时间序；
- 基期月等于统计月的自指记录（基期本身，指数恒为 100）不含比较信息，建图时
  自动跳过。
